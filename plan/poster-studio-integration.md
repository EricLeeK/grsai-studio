# poster-studio Integration Design

> Status: **implemented & verified** (2026-06-24). One terminal, two ports, Grsai-only.

## Goal

Bring **poster-studio** (Next.js 15 + React + Fabric.js canvas editor) into
grsai-studio, launched by a single `bash start.sh`, with **Grsai as the only
image model** (no HiAPI / Jimeng / Seedream keys).

## Final architecture (one terminal, two ports)

poster-studio is designed to run at the **document root** — its client
hardcodes root-relative `/api/...` calls, so a `basePath` sub-path proxy breaks
it. It therefore runs at root on its own port; FastAPI owns its own port.

```
bash start.sh                              <- only terminal
  |
  +- FastAPI :8099   (grsai-studio)
  |     |- /            image workbench   (existing)
  |     |- /comic       comic workbench   (existing)
  |     |- /publisher   wechat publisher  (existing)
  |     |- /studio      -> 302 redirect to http://127.0.0.1:8100  (convenience)
  |     |- /api/poster/generate            Grsai wrapper, called by the canvas
  |     `- /output  /reference-images      served with CORS for the canvas origin
  |
  `- Next.js  :8100   (poster-studio, root, AI provider -> FastAPI/Grsai)
```

User-visible: **one `bash start.sh`**, workbench at `http://127.0.0.1:8099/`,
canvas at `http://127.0.0.1:8100/` (or `:8099/studio` which redirects there).
`stop.sh` tears both down.

## Key decisions

- **Two ports, not a single reverse-proxied URL.** Next.js `basePath` does not
  rewrite manual `fetch('/api/...')` calls, so serving poster-studio under
  `/studio` broke every canvas API request. Running it at root on `:8100` is
  robust and matches its design. (Verified: `/api/ai-image` works, assets load.)
- **`next build` + `next start`** (production). No dev/HMR websocket concerns.
- **poster-studio is an external dependency.** `poster-studio/` is gitignored;
  `scripts/setup-poster-studio.sh` clones it, writes `.env.local` (Grsai-only
  provider), and runs `npm install` + `next build`. The launcher auto-runs setup
  if the build is missing.
- **Grsai key stays server-side** (FastAPI only). poster-studio uses its "custom
  compatible provider" pointed at `/api/poster/generate`.
- **CORS** is enabled on FastAPI for the canvas origin (`:8100`) so Fabric can
  load `/output` images with `crossOrigin="anonymous"` — verified the canvas
  stays **export-safe (untainted)**.

## Files

grsai-studio (committed):
- `app/routers/poster.py` — `/studio` redirect + `POST /api/poster/generate`
  (Grsai wrapper, returns `{data:[{url}]}`)
- `app/main.py` — include poster router + `CORSMiddleware` for canvas origin
- `app/config.py` — poster-studio dir/port, public origin, default model,
  CORS origins
- `requirements.txt` — `httpx` (kept for potential future use)
- `start.sh` / `start-bg.sh` / `stop.sh` — dual-process management + first-run
  setup + Node detection
- `scripts/setup-poster-studio.sh` — clone + `.env.local` + install + build
- `.gitignore` — `poster-studio/`, `poster-studio.pid`
- `plan/poster-studio-integration.md` — this doc

poster-studio (generated by setup, NOT committed):
- `.env.local` — custom provider -> `http://127.0.0.1:8099/api/poster/generate`

## Verification

- `GET /studio` -> 302 -> `http://127.0.0.1:8100/`
- `POST :8100/api/ai-image` (poster-studio's own route) -> Grsai -> returns
  `http://127.0.0.1:8099/output/poster/<ts>.png` (1254px, valid PNG)
- CORS preflight `200`; `/output` GET sends `access-control-allow-origin`
- Browser: generated image loads cross-origin with `crossOrigin="anonymous"` and
  the canvas is **untainted** (`getImageData` succeeds) -> export works.

## Notes / trade-offs

- Two URLs instead of one (poster-studio can't be safely mounted under a path).
- Optional poster-studio features needing server keys are left off (Unsplash
  stock photos, Remove.bg, Qiniu persistence, Vercel KV share). Upload/local
  features still work; AI generation is Grsai.
- `NEXT_PUBLIC_*` values are baked at build time — delete
  `poster-studio/.next` and re-run setup if you change them.

## Phase 2: canvas workbench + GRS AI 已生图库

Closes the "two apps aren't connected" gap — the canvas now reads the site's
generated-image library directly.

- **Workbench tile**: `app/templates/apps.html` adds a "画布工作台" card -> `/studio`.
- **`GET /api/poster/library`** (`app/routers/poster.py`): scans `output/`
  recursively, returns images newest-first with absolute `:8099/output/...` URLs.
- **GRS AI 图库 tab**: `scripts/poster-studio-overrides/GrsImageLibrary.tsx`
  (committed) is copied in and wired as a 5th tab in poster-studio's image
  picker by `scripts/patch_poster_studio.py` (idempotent). Manual **刷新** button
  re-fetches (`cache: 'no-store'`) so newly generated images appear on demand.
  Default tab is now this library.
- Verified: picker shows 194 site images; selecting one places it on the canvas
  (export-safe); refresh picks up a newly added image (194 -> 195, newest first).

## Phase 3: canvas UI customization (ports 8099 + 8100)

All applied via `scripts/patch_poster_studio.py` (idempotent) + override files;
re-applied on every `setup-poster-studio.sh` run.

- **Ports**: FastAPI `:8099`, poster-studio `:8100` (was 3000). `PS_PORT` default
  in start/stop scripts; CORS origins + `POSTER_STUDIO_UPSTREAM` updated.
- **Library pagination**: `GrsImageLibrary.tsx` now shows 20/page in a 4-column
  grid (4×5) with prev/next + page indicator; fixed the dialog overflow by
  constraining the flex chain (`min-h-0` + scrollable grid).
- **Dark mode**: new `ThemeToggle.tsx` toggles `.dark` on `<html>`. poster-studio
  ships a full `.dark` CSS-variable block, so the chrome (topbar, sidebars,
  panels, dialogs) flips automatically; the canvas paper is hardcoded `#fff` and
  stays white. `Canvas.tsx` viewport bg switched `#F7F8FA` -> `var(--muted)` so
  the workspace darkens too.
- **Topbar cleanup**: removed the 分享 (Share) button; replaced the hamburger
  menu (设置/打赏/公众号/GitHub/乔木推荐/联系作者) with the ThemeToggle.
- **Removed 去背景 (background removal)**: deleted the section in
  `ImagePropertiesPanel.tsx`, the Remove.bg block in `SettingsDialog.tsx`, and
  the `app/api/remove-bg` route. (`@imgly/background-removal` dep left in place —
  harmless.)
